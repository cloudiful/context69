# v0.16 Migration — v0.15.19 to v0.16.0

Scope: breaking contract cutover for Redmine 362. Baseline `v0.15.19`.
Target `v0.16.0`. No production data migration, no business-semantics change,
no v0.15 route deletion in this release.

Inventory: `docs/contracts/v0.16-inventory.md` (116 operations, frozen
v0.15 surface). Canonical kernel: `crates/context69-contracts`
(`pagination`, `errors`, `ingest`, `projections`, canonical request shapes).

## 1. Freeze and inventory (before deploy)

1. Freeze v0.15.19 clients.
2. Export the endpoint/schema inventory from the v0.15.19 baseline
   (`docs/contracts/v0.16-inventory.md`, `frontend/openapi/context69.openapi.json`).
3. Keep the parity gate green while cutting over:
   `cargo test -p context69 --test contract_surface`.

## 2. HTTP wire: what new clients must send

Paths, methods, and operation counts are unchanged (116 operations, no
`operationId` added or removed). What changed is the request/response shape
advertised in OpenAPI and the validation bounds.

### 2.1 Pagination and sorting kernel

New single source in `crates/context69-contracts/src/pagination.rs`:

- `SortDirection` (`asc`/`desc`) is canonical. `library::SortDirection` is
  removed; `documents::SortOrder` stays only as a deprecated compat alias
  (`Asc`/`Desc` map 1:1 to `SortDirection`).
- `OffsetPageQuery` (`page` 1..=10_000, `page_size` 1..=100),
  `CursorPageQuery` (`limit` 1..=100, `cursor?`),
  `OffsetPagination`, `CursorPagination` (`has_more=true` requires
  `next_cursor`).
- OpenAPI now emits `minimum: 1` for `page`/`page_size`/`limit`
  (v0.15 emitted `minimum: 0` while the runtime rejected 0). Zero is now
  rejected at the schema, validation, and handler layers consistently.

### 2.2 Task list and task items

- `GET /v1/tasks` OpenAPI now uses `CanonicalTaskListQuery`: `view` is
  required, `trashed` is gone, `page` 1..=10_000, `page_size` 1..=100.
  The Rust `TaskListQuery` struct keeps `trashed` only so in-flight legacy
  callers still deserialize; the handler converts
  `CanonicalTaskListQuery -> TaskListQuery` (`trashed: None`) before the
  service call. New clients must send `view` (`processing` for the queue
  first page) and must not send `trashed`.
- `GET /v1/tasks/{task_id}/items` bounds are `limit` 1..=100
  (`TaskItemsQuery` wire default 100). The old SDK hidden `limit=200`
  no longer exists.

### 2.3 Search

- `SearchRequest` keeps deprecated `page` for wire compatibility.
  New code uses `CanonicalSearchRequest` (no `page`, opaque `cursor`,
  `limit` 1..=100, default 8).
- `POST /v1/search` still accepts `SearchRequest`.
- `GET /v1/search/stream` now decodes `CanonicalSearchRequest` through a
  shared decoder: no `page` param, `limit` 1..=100, cursor authoritative.
  Do not send `page` to the stream endpoint.
- `SearchStreamQuery` and `SourceKeyQuery` private duplicates are removed
  from OpenAPI; the stream shares validation/defaults with the canonical
  kernel instead of a second field list.

### 2.4 Ingest options (uploads, batches, URL imports)

New canonical shapes in `crates/context69-contracts/src/ingest.rs`:

- `SourcePolicy`: `retain` (default) | `release_after_processing`.
- `CanonicalUploadMetadata`: same wire keys as
  `LibraryFileUploadMetadata`, but `metadata_json` is `MetadataObject`
  (explicit object map). Scalar/array `metadata_json` fails at
  deserialization; JSON Schema advertises an object.
- `IngestOptions`: `{ metadata, translation?, extraction?, source_policy }`.

Adoption:

- `FileBatchItem`, `PrepareLibraryUploadRequest`,
  `ImportLibraryFileFromUrlRequest` gain `options?: IngestOptions`.
  When present it takes precedence; when absent the handler falls back to
  the flattened v0.15 fields (`metadata`/`translation`/`extraction`/
  `delete_source_after_processing`). `with_ingest_options()` dual-writes
  both shapes for in-flight readers.
- Multipart `metadata` accepts either the legacy flattened document or a
  bare `IngestOptions` document. Non-object `metadata_json` keeps the
  preserved 422 `metadata_json must be an object` in both shapes.
- `delete_source_after_processing=false` means `Retain`, `true` means
  `ReleaseAfterProcessing`. New clients send only `options.source_policy`.

### 2.5 Search settings secret

- `PUT /v1/settings/search` OpenAPI now uses
  `CanonicalUpdateSearchSettingsRequest` with
  `api_key: SecretPatch` (`{op: keep|set|clear}`, `Keep` default).
  The Rust `UpdateSearchSettingsRequest` (`api_key`/`clear_api_key`)
  stays for the service boundary; the handler converts
  `SecretPatch -> (api_key, clear_api_key)` (`Keep -> (None,false)`,
  `Set(v) -> (Some(v),false)`, `Clear -> (None,true)`).
  New clients send `{op:"keep"}`, `{op:"set",value:"..."}`, or
  `{op:"clear"}` (frontend `settings-payloads.ts` already does this).

### 2.6 Errors

- New `ApiErrorCode` (`invalid_argument`, `unauthorized`, `forbidden`,
  `not_found`, `conflict`, `payload_too_large`, `unprocessable_entity`,
  `rate_limited`, `upstream_error`, `unavailable`, `upstream_timeout`,
  `internal`) plus `CanonicalApiErrorResponse` and typed `DomainError`
  constructors. Handlers map typed variants once; no handler classifies by
  message substring. Wire `ApiErrorResponse.code` stays a string for
  compatibility; clients should match on the stable code string, not on
  message text or status alone.

## 3. SDK (`context69-sdk` 0.16)

### 3.1 Facade renames (verb-first, explicit)

| v0.15 name | v0.16 canonical | Notes |
|---|---|---|
| `text_batch` | `submit_text_batch` | old name deprecated alias, same path/body |
| `url_batch` | `submit_url_batch` | deprecated alias retained |
| `file_batch` | `submit_file_batch` | deprecated alias retained |
| `delete_batch` | `submit_delete_batch` | deprecated alias retained |
| `task` | `get_task` | deprecated alias retained |
| `tasks` | `list_tasks(&TaskListOptions)` | `TaskListQuery` overload deprecated; `view` required, default `processing`/1/25 |
| `task_items` | `list_task_items(id, &TaskItemsOptions)` | default `limit=100`, `cursor` omitted when `None`; no hidden 200 |
| `delete_task` | `purge_trashed_task` | canonical for `DELETE /v1/tasks/{task_id}`; old name deprecated alias |
| `release_file_source` | `release_file_source` (unchanged) | maps to `release_group_library_file_source` |

All deprecated aliases still compile and hit the same operation in this
release; they are removed after the controlled cutover (step 5). New code
must use the canonical names.

`TaskListOptions { view, page 1..=10_000, page_size 1..=100, query?,
kind?, status?, stage?, waiting_reason?, dependency_key?, sort_by?,
sort_direction? }` maps 1:1 to `CanonicalTaskListQuery` via
`as_canonical_query()` (validated client-side, no I/O on bad bounds).
`TaskItemsOptions { limit 1..=100, cursor? }` maps to `TaskItemsQuery`
via `as_wire_query()`. `search_compact` keeps the same
`SearchPagination` (`next_cursor`/`has_more`) as `search`; it is a
bounded 320-char snippet projection, no longer lossy.

Every type needed to construct a facade call is re-exported from
`context69_sdk` alone (`TaskListView`, `TaskItemsQuery`, `SortDirection`,
`SourcePolicy`, `IngestOptions`, `CanonicalSearchRequest`,
`CanonicalUploadMetadata`, `SecretPatch`, `SearchPagination`, ...).
Do not import `context69_contracts` directly from SDK callers.

### 3.2 Raw transport (all 116 operations)

`client.raw()` is the complete low-level surface, mechanically aligned
with OpenAPI (`crates/context69-sdk/src/raw_operations.rs`, sorted by
`operation_id`):

- `OPERATIONS` carries `id`/`method`/`path_template`/`requires_auth`/
  `body_kind`/`request_schema`/`response_schema`/`success_status`/
  `idempotent`. `find_operation`/`operation_ids`/`RawRequest`/`RawResponse`
  are the only entry points; there are no per-operation typed methods.
- `requires_auth=false` only for `healthz`, `login`, `logout`; every other
  operation sends `Bearer`. Path params render with percent-encoding;
  missing params fail before I/O. Queries are explicit (`query`/
  `query_opt`); GET sends no body.
- `idempotent=true` only for the six task-submitting operations
  (`submit_text_batch`, `submit_url_batch`, `submit_file_batch`,
  `submit_delete_batch`, `submit_task`, `submit_vector_index_rebuild`)
  via `with_auto_idempotency_key()` (`ctx69-sdk-*` derived from endpoint
  plus body). Multipart uploads take pre-encoded bytes via `raw_body`;
  `search_stream` returns SSE bytes for the caller to parse.

## 4. MCP (protocol adapter, not HTTP passthrough)

Tool names are frozen (6): `search_documents`, `get_document`,
`query_documents`, `get_document_by_external_id`, `get_documents`,
`list_sources`. Inputs never reuse HTTP DTOs; outputs use only bounded
projections (`crates/context69-contracts/src/projections.rs`).

- `search_documents` takes `McpSearchRequest` (`query`, `group_path?`,
  `source_key?`, `locale?`, `limit` 1..=20 default 8, `cursor?`;
  `deny_unknown_fields`). No `page`, no published window, no
  `metadata_filters`, no sort mode. Structured filtering stays behind
  `query_documents`.
- `query_documents` omitted `limit` defaults to the MCP-local 20 (HTTP
  DTO default 50 never applies); explicit `limit` must be 1..=20.
- `get_document` chunk window `chunk_limit` 1..=50 default 20, chunk text
  4000 chars; `get_documents` 1..=20 keys with at most five chunks per
  item; search snippets 600 chars. Bounds appear in JSON Schema
  (`maxItems`/`maxLength`/`range`) and are enforced at runtime with
  `invalid_params` fix hints.
- `list_sources` returns `McpSourceSummary` (`group_path`, `source_key`,
  `display_name`, `description?`, `visibility`, `origin_status`) with
  `limit` 1..=100 default 50 plus `cursor`. It never returns
  `SourceStatus`; `connection`, `base_query`, `origin_message`, and
  database state are not disclosed over MCP.
- Every `has_more=true` response carries a continuation token
  (`next_cursor`/`next_chunk_cursor`) by construction. Resource listing
  honors the incoming `PaginatedRequestParams.cursor` offset.
- See `docs/mcp.md` for the executable tool examples; parameter/filter
  errors return MCP `invalid_params` with a `fix` message.

## 5. Frontend

- No handwritten wire schemas. Import `SearchSort`, `SortDirection`,
  `UpdateSearchSettingsRequest` (= `CanonicalUpdateSearchSettingsRequest`),
  and all request/response types from the generated OpenAPI via
  `src/services/api/api-types.ts`. `SearchSortMode` in `src/types/ui.ts`
  is a deprecated alias for `SearchSort`.
- Task queue wrappers always send `view`, never `trashed`.
- Search settings saves send `SecretPatch` (`settings-payloads.ts`).
- Regenerate after every backend contract change:
  `bun run generate:api:from-backend` (exports
  `frontend/openapi/context69.openapi.json`, then regenerates
  `src/generated/openapi.ts`). Generated files are the contract; never
  hand-edit them.

## 6. Deploy together (breaking cutover)

```text
v0.15.19 -> v0.16.0
1. freeze v0.15.19 clients and export an endpoint/schema inventory
2. deploy v0.16 server and generated frontend together
3. publish context69-sdk 0.16 with renamed methods and no legacy task/upload fields
4. validate MCP tool schemas and rotate MCP clients
5. remove v0.15 compatibility fields and adapters after the controlled cutover
```

Rules for this release:

- Deploy the v0.16 server and the regenerated frontend together; do not
  mix a v0.15 frontend with a v0.16 server (task `view`, stream `page`,
  and `SecretPatch` shapes differ in OpenAPI).
- Publish SDK 0.16 with the canonical facade plus `raw()`; keep the
  deprecated aliases until step 5, then remove them in one versioned
  change.
- Rotate MCP clients after validating tool schemas
  (`cargo test -p context69 --test mcp_contracts --test mcp_tool_shapes`);
  anonymous callers must only ever see `McpSourceSummary`.
- Do not delete v0.15 compatibility routes, fields, or adapters in this
  release. Removal needs explicit operator confirmation and happens only
  in step 5, after the cutover is validated.
- No source-data migration in the contract release. No PostgreSQL
  retention, S3 retention, Qdrant indexing, or file/task semantic change.

## 7. Release gate

```bash
cargo fmt --check
cargo test --workspace
cd frontend && bun run generate:api:from-backend && bun run check && bun run test && bun run build:with-api
git diff --exit-code -- frontend/openapi/context69.openapi.json frontend/src/generated/openapi.ts
```

Plus: workspace, frontend, and OpenAPI versions are all `0.16.0`;
generated artifacts are clean (`git diff --exit-code`); an SDK-only
example compiles without importing `context69-contracts` directly
(`crates/context69-sdk/tests/contract_paths.rs`,
`crates/context69-sdk/tests/raw_transport.rs`).

## 8. Rollback

Rollback is a version rollback to v0.15.19 plus the v0.15 MCP/client
artifacts. Do not partially roll back only one generated contract layer
(OpenAPI, frontend types, SDK transport, and MCP adapters move together).

## 9. Non-goals

- Task pause/resume remains issue #349.
- Production file-state migration remains issue #350.
- No change to PostgreSQL document retention, S3 source retention,
  Qdrant indexing, or file/task business semantics.
