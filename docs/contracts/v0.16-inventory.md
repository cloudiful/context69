## Conventions

- One row per HTTP operation defines the frozen contract. Format is fixed:
- `operation_id | method | path_or_tool | request_schema | response_schema | errors | sdk_surface | mcp_surface | visibility`
- In markdown the header is `| operation_id | method | path_or_tool | request_schema | response_schema | errors | sdk_surface | mcp_surface | visibility |`.
- `request_schema` is the JSON `requestBody` schema name, `multipart-form` for file uploads, or `-` when there is no JSON body (path/query params only; query structs are flattened in OpenAPI and listed under Shared schemas).
- `response_schema` is the first 2xx JSON schema name, `array<X>` for array items, `A+B` for multiple distinct 2xx schemas (deduped), or `-` for empty (204/no content).
- `errors` lists non-2xx responses as `CODE` (empty body) or `CODE:Schema` (JSON body), joined by `;`, or `-` when none.
- `sdk_surface` is `high-level` when `context69-sdk` has a dedicated facade method for the operation, else `none`. No `raw` transport exists yet (Task 4).
- `mcp_surface` is `none` or a comma-separated list of `tool:<name>` / `resource:<uri-template>`.
- `visibility` is `public` (no auth), `authenticated` (login required, scopes enforced per router layer), or `admin` (`/v1/admin/*` or translation admin scope).
- Machine check (`tests/contract_surface.rs` + `src/api/docs.rs` test): no duplicate `operation_id`, every OpenAPI `operationId` appears once in this table and vice versa with matching method/path, every non-`-` schema token appears in OpenAPI `components.schemas` and in Shared schemas.
